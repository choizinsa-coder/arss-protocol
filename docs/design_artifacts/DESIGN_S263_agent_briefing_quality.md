# AIBA 에이전트 브리핑 품질 — 분석 및 적용 선언

**세션**: S263 / **날짜**: 2026-06-18

## 1. 핵심 발견 (도미 분석)
답변 품질 차이는 질문자 위치가 아닌 프롬프트 구조에서 발생.
캐디 의뢰: 작업 중심 → 탐색 공간 넓음 → 품질 ~70
비오 중개: 배경·실패·목표·제약 포함 → 탐색 공간 축소 → 품질 ~95

품질 차이 메커니즘 3가지:
1. 문제 프레이밍 효과 — 왜+실패+피할것 동시 제공 시 탐색 공간 급감
2. 메타 목표 제공 — 상위 목적이 있을수록 LLM은 일관된 결과 생성
3. 반례 정보 — 실패 사례가 설계 요청보다 더 많은 정보를 줌

오해 교정: 비오가 CEO라서가 아님. 메시지의 맥락 밀도 차이가 원인.

## 2. 캐디 즉각 적용 선언 (S263~)
모든 에이전트 의뢰 표준 구조:
[CONTEXT]    배경 — 왜 이 작업이 필요한가
[HISTORY]    실패 사례 — 이전에 무엇이 왜 실패했는가
[GOAL]       목표 — 무엇이 달성되면 성공인가
[CONSTRAINT] 제약 — 반드시 피해야 할 것
[REQUEST]    요청 — 구체적으로 무엇을 만들어야 하는가

## 3. 3-6 재정의 방향
기존: 비오님을 병목에서 제거
재정의: 비오님이 제공하는 수준의 맥락을 시스템이 자동으로 전달하게 만드는 구조
구현: 브리핑 템플릿 표준화(방법2) + 실패→브리핑 강화→재설계 루프(방법3)

## 4. S263 적용 사례
3-5 설계 1·2차(캐디 직접): NOT IMPLEMENTABLE — 작업 중심, 실패 사례 미포함
3-5 설계 3차(비오 중개): IMPLEMENTABLE — 실패 사례+제약+성공 기준 포함
